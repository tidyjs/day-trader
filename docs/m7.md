## M7: what is built
- **`src/run.py`:** the scheduled entrypoint. A pure `decide(now_et, is_trading_day, scan_exists)` returns scan / skip / alert:
  - before 09:15 ET: skip
  - 09:15-10:00 ET: scan (marked late after the 09:30 open)
  - after 10:00 ET with no scan for today: failure alert
  - non-trading day or today's scan already saved: skip (idempotent)
  - The scan always runs **as of 09:15 ET**, so a late GitHub start sees the same data cutoff as an on-time one.
- **`.github/workflows/scan.yml`:**
  - cron `15 13 * * 1-5` (09:15 EDT), `15 14 * * 1-5` (09:15 EST), and a backstop `30 15 * * 1-5` (10:30 EST / 11:30 EDT) that alerts if no scan exists
  - a concurrency group, so a delayed off-season run waits and then exits quietly
  - commits `data/` back after every run, failures included
  - secrets only from GitHub secrets
  - Python 3.12.12
- **`src/alerts.py`:** all communications are Markdown files in the repo (your choice, 2026-11-16; Gmail was removed).
  - One file per message: `messages/YYYY/MM/YYYY-MM-DD_HHMM_<kind>.md`.
  - `messages/LATEST.md` holds the newest message in full, plus links to the 30 before it.
  - The workflow commits `messages/` and `data/` back after every run, failures included.
  - A "Scanner failed" message is written at most once a day by the backstop.
  - A failure also exits non-zero, so the GitHub run fails and GitHub notifies the repo owner. Committed files alone send no notification.
  - Shortlist, no-trade and recap messages use the same module in M5.
- **Each run's summary** says whether the halts feed has shown NYSE yet (`halts feed: NYSE not seen yet (N weekday(s) of fetches …)`).

## Item 6 proposal: classify each name 3 times (not implemented)
- **Calls:** three independent calls per company with the same prompt. Each is validated with one retry. All three outputs are saved in `inputs.catalyst[sym].runs`, so replays still never call the model.
- **Deterministic combination:**
  - **promo disqualifier** only if at least 2 of 3 runs say `promo_or_pump_flag` true or type `promo`
  - **dilution:** a single run is enough for the warning
  - **catalyst_type:** majority of 3; if all three differ, it's `unclear`, which counts as no verified catalyst
  - **"no catalyst" disqualifier:** only if at least 2 of 3 say `none` (and no volume surge)
  - **quality:** the median of the three
  - **merger-target warning:** if at least 2 of 3 say merger and `acquisition_target`
  - **availability:** fewer than 2 valid runs means "classifier unavailable" (a warning, rule unknown)
- **Agreement is logged per name** (e.g. `promo 1/3`) so the funnel can show how often runs disagree.
- **Cost:** today's mean is 5.8 model calls, 8,399 input and 625 output tokens, about $0.0012 per scan day. Three runs is about **17.4 calls and $0.0036 per scan day** (max day 11-13: $0.0023 → about $0.0069), roughly **$0.08 a month** at 21 trading days. It adds about 2-3 s per name if run one after another (well under a minute a day), or none if the three calls run in parallel.
- **Why:** between the M3 run and the hardened run, 2 of 29 model-called names changed flags (YMAT promo True→False and dilution False→True; LFMD quality 4→3 and dilution True→False). Temperature can't be fixed on this model.
