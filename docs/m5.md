# M5: messages (2026-11-16)

Branch `m5-messages` (off `m4-levels`). Not committed. **Waiting on your review of the format before M6.**

## Messages (`src/shortlist.py`)
- **Shortlist** (`kind: shortlist`): Tier A, then Tier B, then Watch, at most 5 names in total. Each name shows:
  - price, gap and prior close
  - premarket high, both full session and the 60 minutes to the cutoff
  - premarket dollar volume and trades
  - float and its source
  - catalyst type, quality and the agreement of the 3 runs
  - a ✓ ✗ ? – line for every rule
  - warnings
  - for Watch names, why they aren't tiered
- **Banners:** "⚠️ REVERSE SPLIT POSSIBLY PENDING" (with filing links) and "⚠️ MERGER TARGET: price likely pinned to deal terms". Scoring is unchanged.
- **Never shown:** trigger, stop, share counts or targets.
- **Every message** starts with "Levels use data up to about 08:59 ET. Re-check the live premarket high at the open."
- **No names today** (`kind: no_trade`): when nothing reaches Tier A, Tier B or Watch, with where each candidate stopped.
- **Scanner failed** (`kind: scanner_failed`): "No shortlist today", a warning not to use an earlier shortlist, where to look, and the error in a collapsed section.
- **Watch (pre-declared 2026-11-16, SPEC 4.4c):**
  - Who qualifies: on T212, passes price and gap, at least $100k premarket dollar volume, in no tier.
  - Excluded, and listed under "Not shown" as "excluded from Watch": an offering disqualifier, or a **pending** reverse split ("possible" does not exclude). Only names that meet every other Watch condition get that label.
  - Names whose only disqualifier is no catalyst or promo/pump can be on Watch, with a banner: **WATCH: NO VERIFIABLE CATALYST**, **WATCH: PROMO / PUMP FLAGGED**, or **WATCH: in no tier**.
  - Ordered by premarket dollar volume. `candidates.csv` → `watch_reason` (`no_catalyst` / `promo` / `other`).
- **Test Issue:** Run workflow → `mode: test_message` writes "TEST: notification check …", which the workflow opens as an Issue labelled `test`.

## Delivery: files plus GitHub Issues
- Messages are still files in `messages/`, plus `LATEST.md`.
- New workflow step: after the commit, `python -m src.github_issues open` opens **one Issue per new message**:
  - titled with the message's first line, labelled by kind (`shortlist`, `no-names`, `scanner-failed`, `test`), with the message as the body and a link to the file
  - uses the built-in `github.token` (`permissions: issues: write`), so no new secrets
  - if an Issue can't be created, the run fails
- **Optional repository variable `NOTIFY_USER`** (your GitHub username, not a secret): the Issue then ends with `cc @<you>`, a direct mention.

See `docs/m5_samples.md` for all six samples.
