# Milestone 1: scanner

Universe, prior close, gap %, T212 filter and the candidate log (SPEC 4.1, 4.4a).

## Run

```
.venv/bin/python -m src.scan                         # live, now (ET)
.venv/bin/python -m src.scan --date 2026-11-13       # as of 09:15 ET that day
.venv/bin/python -m src.scan --replay data/scans/2026-11-13.json
.venv/bin/python -m pytest -q
```

## How it avoids look-ahead

- **Data cutoff** = scan time minus 16 min, rounded down to the minute. At 09:15 ET that's 08:59.
- Only 1-min SIP bars that *closed* by the cutoff are fetched, saved or scored. The bar that starts at the cutoff is dropped, because the bars API includes it.
- Prior close is the previous session's SIP daily close. Checked against minute bars: it is the official 16:00 close, not the after-hours last trade.
- `evaluate()` is a pure function of the saved inputs, with no network or clock. `--replay` re-runs it from the scan file alone and fails if anything differs.

## Files

- `data/scans/YYYY-MM-DD.json`: inputs and outputs for each scan.
  - Inputs: universe, prior closes, premarket bars, and a reference to the T212 list.
  - Full bars are kept only for candidates. Other symbols keep only their last bar, which is enough to reproduce that they failed. About 0.6 MB a day.
- `data/candidates.csv`: one row per name that passes price and gap, with a pass/fail flag per rule. Re-running a day replaces that day's rows.
- `data/t212/YYYY-MM-DD.json`: the T212 US stock list for each day (matched on `shortName`) plus a hash. A replay fails if the file has changed since the scan.

Every historical run carries two warnings (SPEC 7 caveat): the T212 list and the Alpaca universe are today's, not the scan day's.

## Bugs found while building

- `ALPACA_TRADING_URL` copied from Alpaca's dashboard ends in `/v2`, which gave 404s. The client now accepts it with or without `/v2`. (The M0 scripts never read this variable, so M0 used the default URL.)
- The bars API returned the bar starting at the cutoff. It is now dropped before saving.
